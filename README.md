# MUSE GANTT

iPhone で使う、ガントチャート型のタスク・工程管理アプリ。AIエージェント「MUSE」が実際のタスクデータを読み、作業可能な時間帯だけを使って計画を提案します。

## 画面

- 上部：日付（‹ › で移動、タップで日付選択）・日／週／月の切り替え・MUSE
- 中央：ガントチャート（画面の約85%）。ページ全体は縦にも横にもスクロールしません。タスクが多いときだけチャート内が縦にスクロールし、ピンチで拡大したときだけ横にスクロールします
- 下部：今日／一覧／＋／実績／設定
- 詳細・追加・MUSE・一覧はボトムシートで開きます

## 操作

| やりたいこと | 操作 |
|---|---|
| 詳細を見る | バーかタスク名をタップ |
| 日時を動かす | バーを長押ししてドラッグ（日表示は15分単位、拡大すると5分単位） |
| 所要時間を変える | 選択中のバーの両端のつまみをドラッグ |
| 拡大・縮小 | チャートをピンチ（日表示は拡大に応じて目盛りが1時間→30分→15分） |
| 完了／戻す | タスク名左の丸をタップ |
| 開始・中断・再開 | 詳細シートのボタン（実績の時刻を記録） |
| 追加 | ＋、または空いている所を長押し（その時刻で追加） |
| 文章で追加 | 「明日 3号機 治具調整 45分」「金曜まで 報告書 2h 重要」など。時刻を書かなければ空き時間へ自動配置 |
| 取り消し | 変更直後のトーストの「元に戻す」 |

## 色と表示

- 深緑：通常 ／ 真鍮色：重要 ／ 赤：遅延・期限超過 ／ 灰：完了 ／ 青灰：プライベート
- バー内の濃い部分が進捗率、バーの下の細い線が実績、赤い旗が期限、ひし形がマイルストーン
- 破線のバーは MUSE の提案（まだ保存されていない）
- 斜線は製造部門の休憩（初期値 10:15–11:00）、薄い灰は勤務時間外・休日

## 作業可能条件（設定で変更可）

- 通常勤務 8:30–17:30（平日）
- 工程調整・改造／設備停止：製造部門の休憩中か休日だけ
- 休日作業：休日の勤務時間帯
- 工場カレンダーの休日を追加可能
- 勤務予定と、実際の出退勤（実績タブ）は別々に記録し、時間外・休日出勤を集計

ドラッグで条件外に置こうとすると確認が出ます。前工程より先に置いた場合や期限を超える場合は通知し、後続タスクと重なると「後続を調整」で条件を満たす次の空き時間へ自動で移せます。

## MUSE

MUSE はチャットではなく、アプリと同じデータを読み書きするエージェントです。使える道具は次の4つで、時刻はすべてアプリ側の計算から選ばせています。

| ツール | 内容 | 保存 |
|---|---|---|
| `find_slots` | 勤務時間・休憩・休日・既存予定を満たす空き時間を返す | しない |
| `simulate_change` | 延長・移動したときの後続のずれと期限超過を計算 | しない |
| `propose_plan` | 作成・移動・期限/担当の変更・削除をまとめて提案。条件違反や重複はエラーで差し戻し | 承認後に保存 |
| `update_task` | 進捗・状態・メモ・優先度・名称を直接更新 | すぐ保存（履歴に MUSE と記録） |

提案はチャートに破線で表示され、「承認して反映」を押すまで保存されません。各タスクの変更履歴には「自分／MUSE」と判断理由が残ります。

## 2つの動かし方

### 1. claude.ai のアーティファクト（推奨）

- データは claude.ai 側のデータベースに保存され、同じアカウントでサインインした端末間で同期します（読み書きできるのは所有者と編集者だけ）
- MUSE は Claude に接続され、実データを操作します。初回だけ利用の許可を求められます
- オフライン時は直前のデータを表示し、変更は端末にも保存します

### 2. このリポジトリ（GitHub Pages など）

- `index.html` をそのまま配信すると、ホーム画面に追加できる PWA として動きます（`sw.js` でオフライン起動）
- データはその端末のブラウザ内だけに保存されます（同期なし）
- Claude の外なので MUSE は接続されません。代わりに同じ処理を `window.MUSE` として公開しています

```js
MUSE.listTasks()
MUSE.findSlots(45, 'line', '2026-11-04 08:00', '2026-11-10 18:00')
MUSE.simulateChange(taskId, { extendMin: 120 })
MUSE.proposePlan({ summary, reason, ops: [{ op: 'move', task_id, start, end }] })
MUSE.approve(proposalId)
```

外部のエージェントや API と接続するときは、この関数群を呼べばチャートと同じデータ・同じ制約チェックを通ります。

## データ

各タスクは次を持ちます：`id, name, project, kind, start, end（予定）, segs（実績の開始/終了の区間）, progress, status, priority, important, deadline, deps（前工程）, milestone, assignee, memo, history（変更履歴と理由）, rev, updatedAt`。

ほかに `proposals`（MUSEの提案と承認状態）、`meta/settings`（勤務条件）、`attendance/YYYY-MM`（出退勤）。設定の「全データをコピー」で JSON を取り出せます。

## 実装範囲と制約

- 同時編集はタスク単位で後勝ち。MUSE の提案を承認するとき、提案後に対象が変わっていれば確認を出します
- 音声入力は iPhone のキーボードのマイクを使います（ページ内の音声認識はアーティファクトでは使えません）
- Google カレンダー等との連携は未接続です。日時はすべて時刻値で持ち、`window.MUSE` 経由で同期処理を足せる構造にしています
- リマインド通知は未実装です
