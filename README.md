# MUSE GANTT

iPhone で使う、ガントチャート型のタスク・工程管理アプリ。AIエージェント「MUSE」が実際のタスクデータを読み、作業可能な時間帯だけを使って計画を提案します。

## 画面

- 上部：日付（‹ › で移動、タップで日付選択）・日／週／月／大日程の切り替え
- 中央：ガントチャート（画面の約85%）。行ごと・日ごとに区切り線があります。ページ全体は縦にも横にもスクロールしません。タスクが多いときだけチャート内が縦にスクロールし、ピンチで拡大したときだけ横にスクロールします
- 下部：今日／一覧／＋／その他（出退勤・休み・MUSE・実績・設定）
- 詳細・追加・MUSE・一覧・設定は画面中央のカードで開き、外側をタップすると閉じます

## 表示の切り替え

| 表示 | 1列 | 使いどころ |
|---|---|---|
| 日 | 時刻（6:00–20:00） | その日の段取り。15分単位で動かす |
| 週 | 1日 | 月〜日。‹ › で1週ずつ送る。月をまたぐ週は前の月の週として「10月 第5週」のように表示。バーは日の枠いっぱいに出て、ドラッグすると1日ずつ動く（時刻はそのまま） |
| 大日程 | 1か月 | 1年分（初期値は4月始まり）を横スクロールなしで俯瞰。項目は週単位で入れて動かす |

- 大日程の「日予定」（日ごとのタスクも一緒に出すか）は、チャート左上で切り替えます
- 日・週・月・大日程とも、チャートの幅は画面幅にそろえています（拡大したときだけ横スクロール）
- ヘッダーと下のタブはどの画面でも共通。一覧・MUSE・その他・詳細では、ヘッダーにページ名と操作ボタンが出ます
- 大日程の1年は設定の「1年の始まり」で決まります（初期値は4月＝年度）。‹ › で1年ずつ移動
- 縦の区切り線は日付・週の見出しから一番下まで通しています

## 操作

| やりたいこと | 操作 |
|---|---|
| 詳細を見る | バーかタスク名をタップ |
| 日時を動かす | バーを長押ししてドラッグ（日表示は15分単位、拡大すると5分単位） |
| 所要時間を変える | 選択中のバーの両端のつまみをドラッグ |
| 拡大・縮小 | チャートをピンチ（日表示は拡大に応じて目盛りが1時間→30分→15分） |
| 完了／戻す | タスク名左の丸をタップ |
| 開始・中断・再開 | 詳細シートのボタン（実績の時刻を記録） |
| 追加 | ＋、または空いている所を長押し（その時刻・その日・その週、その行のプロジェクトで追加） |
| 大日程を追加 | ＋ →「大日程（週ごと）」。開始週と期間（週）を選ぶか、「W46-W48 設計」「11/9から3週 部品手配」と書く |
| 文章で追加 | 「明日 3号機 治具調整 45分」「金曜まで 報告書 2h 重要」など。時刻を書かなければ空き時間へ自動配置 |
| 取り消し | 変更直後のトーストの「元に戻す」 |

## 色と表示

- 深緑：通常 ／ 真鍮色：重要 ／ 赤：遅延・期限超過 ／ 灰：完了 ／ 青灰：プライベート
- バー内の濃い部分が進捗率、バーの下の細い線が実績、赤い旗が期限、ひし形がマイルストーン
- 破線のバーは MUSE の提案（まだ保存されていない）
- 濃い灰の枠は大日程、四角いチェックは大日程の項目
- 薄い灰は勤務時間外・休日、赤い縦線は現在時刻
- 製造部門の休憩（初期値 10:15–11:00）はチャートには出さず、工程調整・改造の自動配置にだけ使います

## 休み・休日出勤・振替

週・月表示で日付の見出しをタップ（日表示は左上の「平日／休日」ボタン、または「その他」→「今日の区分」）すると、次の4つをワンタップで登録できます。

| 区分 | 登録できる日 | 自動配置 |
|---|---|---|
| 休み | 勤務日 | 仕事を入れない |
| 振替休日 | 勤務日 | 仕事を入れない。振替出勤と1日ずつ対応 |
| 休日出勤 | 休日 | 勤務時間に仕事を入れる。時間は休日出勤として集計 |
| 振替出勤 | 休日 | 勤務時間に仕事を入れる。あとで振替休日が1日必要 |

振替出勤と振替休日は日付順に1対1で対応させ、数が合わないと「その他」に赤い点が付き、「振替休日があと◯日足りません」「振替出勤のない振替休日が◯日」と表示します。「その他」の「振替」で対応表を確認できます。

## 作業可能条件（設定で変更可）

- 通常勤務 8:30–17:30（平日）
- 工程調整・改造／設備停止：製造部門の休憩中か休日だけ
- 休日作業：休日の勤務時間帯
- 工場カレンダーの休日を追加可能
- 勤務予定と、実際の出退勤（実績タブ）は別々に記録し、時間外・休日出勤を集計

ドラッグで条件外に置こうとすると確認が出ます。前工程より先に置いた場合や期限を超える場合は通知し、後続タスクと重なると「後続を調整」で条件を満たす次の空き時間へ自動で移せます。

## MUSE

MUSE はチャットではなく、アプリと同じデータを読み書きするエージェントです。使える道具は次の4つで、時刻はすべてアプリ側の計算から選ばせています。

| ツール | 内容 | 保存 |
|---|---|---|
| `find_slots` | 勤務時間・休憩・休日・既存予定を満たす空き時間を返す | しない |
| `simulate_change` | 延長・移動したときの後続のずれと期限超過を計算 | しない |
| `propose_plan` | 作成・移動・期限/担当の変更・削除をまとめて提案。条件違反や重複はエラーで差し戻し | 承認後に保存 |
| `update_task` | 進捗・状態・メモ・優先度・名称を直接更新 | すぐ保存（履歴に MUSE と記録） |

提案はチャートに破線で表示され、「承認して反映」を押すまで保存されません。提案カードの「チャート」でその日付へ移動して破線を確認できます。各タスクの変更履歴には「自分／MUSE」と判断理由が残ります。

### 遅延の検出と再計画

予定の終了を過ぎても完了していないタスクは赤で表示され、MUSE ボタンに赤い点が付きます。MUSE の「遅延N件を再計画」（または一覧の「再計画を提案」）を押すと、次の手順で再計画を提案します。AI を使わない決まった計算なので、MUSE 未接続でも動きます。

1. 遅延タスクを 重要 → 期限が近い → 予定が早い 順に並べる
2. 途中まで進んだものは残りの作業時間（15分単位）、未着手は元の所要時間で、作業可能条件と既存予定を満たす直近の枠を探す
3. 前工程が動いたことで重なる後続タスクも、前工程の後ろの枠へずらす
4. まとめて1つの提案にし、承認されたら保存（履歴に MUSE と理由を記録）

計画 → 実行（開始・中断・完了で実績を記録）→ 進捗確認 → 遅延検出 → 再計画 → 承認 → 計画更新 の流れが、すべて同じデータ上で回ります。

## 2つの動かし方

### 1. claude.ai のアーティファクト（推奨）

- データは claude.ai 側のデータベースに保存され、同じアカウントでサインインした端末間で同期します（読み書きできるのは所有者と編集者だけ）
- MUSE は Claude に接続され、実データを操作します。初回だけ利用の許可を求められます
- オフライン時は直前のデータを表示し、変更は端末にも保存します

### 2. このリポジトリ（GitHub Pages など）

- `index.html` をそのまま配信すると、ホーム画面に追加できる PWA として動きます（`sw.js` でオフライン起動）
- データはその端末のブラウザ内だけに保存されます（同期なし）
- GitHub版（このリポジトリ）は有料のAI接続を使いません。MUSEは「今日やる順番」「遅れの立て直し（再計画の提案）」「次の空き時間」の計算機能だけで動きます
- 同じ処理を `window.MUSE` として公開しています（遅延の再計画も使えます）

```js
MUSE.listTasks()
MUSE.findSlots(45, 'line', '2026-11-04 08:00', '2026-11-10 18:00')
MUSE.simulateChange(taskId, { extendMin: 120 })
MUSE.proposePlan({ summary, reason, ops: [{ op: 'move', task_id, start, end }] })
MUSE.approve(proposalId)
MUSE.replanLate()   // 遅延タスクの再計画を提案として作成
```

外部のエージェントや API と接続するときは、この関数群を呼べばチャートと同じデータ・同じ制約チェックを通ります。

## データ

各タスクは次を持ちます：`id, name, project, kind, scale（time=日・時刻、week=大日程）, start, end（予定）, segs（実績の開始/終了の区間）, progress, status, priority, important, deadline, deps（前工程）, milestone, assignee, memo, history（変更履歴と理由）, rev, updatedAt`。

ほかに `proposals`（MUSEの提案と承認状態）、`meta/settings`（勤務条件）、`attendance/YYYY-MM`（出退勤）。設定の「全データをコピー」で JSON を取り出せます。

## 実装範囲と制約

- 同時編集はタスク単位で後勝ち。MUSE の提案を承認するとき、提案後に対象が変わっていれば確認を出します
- 音声入力は iPhone のキーボードのマイクを使います（ページ内の音声認識はアーティファクトでは使えません）
- Google カレンダー等との連携は未接続です。日時はすべて時刻値で持ち、`window.MUSE` 経由で同期処理を足せる構造にしています
- リマインド通知は未実装です

## 品質確認

`app.html` を変えたら `python3 build.py` で `index.html` を作り直します。次の項目を iPhone SE／15／15 Pro Max の Safari 表示・ホーム画面表示（計6サイズ）で自動確認しています。

- ページ全体の縦横スクロールが出ない（空・日・週・月・詳細シート・MUSE・40件表示）
- チャートが画面の84〜89%を使う
- バーの左右端が時刻目盛りと1px以内で一致（再読み込み後も）
- 長押しドラッグで1時間移動、端のつまみで+30分 → 保存 → 再読み込み後も保持
- ピンチで×3まで拡大し、チャート内だけ横スクロール
- 空き部分の長押しで追加シート（指を離したときの誤タップなし）、文章からの自動配置
- MUSE：条件違反の提案は差し戻し、提案は破線・未保存、承認で保存と履歴、遅延の再計画
